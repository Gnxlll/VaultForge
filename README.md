# VaultForge

VaultForge is a desktop application for securely storing project metadata, secrets, and files. It uses a Rust/Tauri backend with an SQLite database and a React + TypeScript frontend built with Vite and Tailwind.

## Tech stack

- Backend: Rust + Tauri
- Database: SQLite (rusqlite)
- Frontend: React + TypeScript, Vite, Tailwind CSS
- Bundling: Tauri for native desktop builds

## Key features

- Project management (create, edit, delete projects)
- Vault for secrets and secure files (encryption handled in Rust)
- Password and secret generators with configurable options
- File operations via Tauri commands

## Quick start (development)

Prerequisites: Node.js, npm (or yarn), Rust toolchain (rustup + cargo). On Windows ensure build tools required by Tauri are installed.

1. Install frontend dependencies:

```bash
npm install
```

2. Run the frontend dev server:

```bash
npm run dev
```

3. Run backend tests (from the project root):

```bash
cd src-tauri
cargo test
```

4. Run the full Tauri app in dev mode (when ready):

```bash
npm run tauri dev
```

## Build

```bash
npm run build
cd src-tauri
cargo build --release
tauri build
```

## Tests

- Frontend: `npm test` (Vitest)
- Backend: `cargo test` in `src-tauri`


# 📖 Usage Guide

After installing and running VaultForge, you can use it to securely manage your project data, secrets, and files.

## 1. Launch the Application

For development, start VaultForge using:

```bash
npm run tauri dev
```

To use a production build, open the executable generated by the Tauri build process.

```bash
npm run tauri build
```

---

## 2. Create a New Project

Create a project entry to organize your project-related information.

You can add metadata such as:

* Project name
* Description
* Tags
* Other relevant project information

Each project serves as a central location for its associated secrets and files.

---

## 3. Store Secrets

Use the vault to securely store sensitive information such as:

* API keys
* Credentials
* Passwords
* Access tokens
* Other project secrets

VaultForge stores this information **locally** using its SQLite database. Sensitive operations are handled by the Rust backend.

> **Tip:** Avoid storing plaintext credentials in project metadata or other unsecured fields.

---

## 4. Attach Files

Attach project-related files and documents directly to your projects.

This allows you to keep project metadata, secrets, and supporting files organized in one location.

Examples include:

* Configuration files
* Documentation
* Project resources
* Certificates
* Other project-related documents

---

## 5. Search and Organize

Use the VaultForge interface to quickly locate and manage your stored information.

You can organize and access:

* Project metadata
* Stored secrets
* Attached files
* Project-related information

Keeping related information within individual project entries makes it easier to manage multiple projects.

---

## 6. Security Tips

For better security when using VaultForge:

* Use strong passwords and credentials.
* Use **16 or more characters** when generating passwords whenever practical.
* Avoid reusing passwords across different services.
* Do not share sensitive vault data with untrusted users.
* Keep your operating system and VaultForge installation updated.
* Do not expose sensitive information through application logs or screenshots.

### Local Storage

VaultForge is designed around local data storage. Project information and vault data are stored on your device rather than requiring a cloud service.

> **Important:** Local storage does not automatically mean that data is immune to compromise. Protect your device with a strong operating-system password, disk encryption where available, and appropriate access controls.
